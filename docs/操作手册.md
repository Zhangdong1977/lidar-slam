## 2. 启动两辆仿真车

本项目使用 CycloneDDS unicast 发现（禁 multicast，避免多车场景的广播风暴）。各节点通过 `--discovery-address <对端IP>` 声明 unicast peer 互相发现；同机的两辆仿真车（gazebo_1/gazebo_2）通过 loopback 自动发现，互不需配 peer。下面示例假设 sidecar 主机为 `10.0.0.187`。

### 终端 1：启动第一辆车（gazebo_1）

```bash
ssh hello@10.0.0.60
cd /home/hello/lidar-slam
./scripts/launch/dispatch.sh \
  --namespace gazebo_1 \
  --discovery-address 10.0.0.187 \
  --discovery-port 11811 \
  --no-rviz
```

**等待 Gazebo 完全加载**（日志出现 `SpawnEntity` 且不再滚动）后，再启动第二辆车。

### 终端 2：启动第二辆车（gazebo_2）

Gazebo 双车仿真复用同一个 Gazebo 进程，因此两辆车需要连接 sidecar 端同一个 Discovery Server。第二辆车仍需使用 `--skip-cleanup --no-gazebo`，避免清理或重复启动第一辆车已经拉起的 Gazebo。

```bash
ssh hello@10.0.0.60
cd /home/hello/lidar-slam
./scripts/launch/dispatch.sh \
  --namespace gazebo_2 \
  --skip-cleanup \
  --no-gazebo \
  --discovery-address 10.0.0.187 \
  --discovery-port 11811 \
  --no-rviz
```

### 参数说明

| 参数 | 作用 |
|------|------|
| `--namespace gazebo_1/gazebo_2` | 为每辆车分配独立 ROS2 namespace，话题分别为 `/gazebo_1/...` 和 `/gazebo_2/...` |
| `--skip-cleanup` | 第二辆车启动前不清理已有 ROS2/Gazebo 进程，避免把第一辆车停掉 |
| `--no-gazebo` | 第二辆车复用第一辆车已启动的 Gazebo 进程 |
| `--discovery-address` | CycloneDDS unicast peer 主机 IP（向后兼容；不再需要端口） |
| `--peer` | CycloneDDS unicast peer 主机 IP（可多次指定多个 peer） |
| `--no-rviz` | 不为每辆车单独启动 RViz（后面统一启动） |

### 默认位姿

| 车辆 | X | Y | Z |
|------|---|---|---|
| `gazebo_1` | `0` | `0` | `0.24` |
| `gazebo_2` | `0` | `2` | `0.24` |

可通过 `--spawn-x`、`--spawn-y`、`--spawn-z` 覆盖。

## 4. 验证

CycloneDDS 模式下 `ros2 topic list` / `ros2 action list` 可正常枚举全图
（service/action 端点发现完整）。若 `ros2 node list` 为空，优先检查两端
`RMW_IMPLEMENTATION=rmw_cyclonedds_cpp`、`ROS_DOMAIN_ID` 一致，且
`CYCLONEDDS_URI` 的 peers 互含对端 IP。

```bash
ros2 node list | grep -E "/gazebo_1|/gazebo_2"
```

可能输出：

```text
/gazebo_1/opentcs_vehicle_node
/gazebo_2/opentcs_vehicle_node
```

关键 topic 首帧验证：

```bash
ros2 topic echo /gazebo_1/joint_states sensor_msgs/msg/JointState --once
ros2 topic echo /gazebo_2/joint_states sensor_msgs/msg/JointState --once
ros2 topic echo /gazebo_1/amcl_pose geometry_msgs/msg/PoseWithCovarianceStamped --once
ros2 topic echo /gazebo_2/amcl_pose geometry_msgs/msg/PoseWithCovarianceStamped --once
ros2 topic echo /gazebo_1/robot_state std_msgs/msg/String --once
ros2 topic echo /gazebo_2/robot_state std_msgs/msg/String --once
```

`/gazebo_1/amcl_pose` 和 `/gazebo_2/amcl_pose` 是给 sidecar / RViz 使用的定位输出。
AMCL 原始输出在车端内部 remap 为 `amcl_pose_raw`，通常不需要 sidecar 订阅。
车辆等待调度时，`robot_state` 中应能看到 `state=IDLE`、`localizationStatus=OK`，
且 `currentTransportOrder` / `goalId` 为空。

手动下发导航目标：

```bash
ros2 topic pub --once /gazebo_1/goal_pose geometry_msgs/msg/PoseStamped \
  "{header: {frame_id: 'map/orderId=G1-TEST'}, pose: {position: {x: 5.0, y: 0.0, z: 0.0}, orientation: {w: 1.0}}}"

ros2 topic pub --once /gazebo_2/goal_pose geometry_msgs/msg/PoseStamped \
  "{header: {frame_id: 'map/orderId=G2-TEST'}, pose: {position: {x: 5.0, y: 2.0, z: 0.0}, orientation: {w: 1.0}}}"
```

物料 action 完整名称如下，sidecar 不应只使用 `/gazebo_1` 或 `/gazebo_2`
作为 action name：

```text
/gazebo_1/load_materials
/gazebo_1/unload_materials
/gazebo_2/load_materials
/gazebo_2/unload_materials
```

## 5. Sidecar 端环境

sidecar 端需切换到 CycloneDDS，并配置 unicast peer 指向车端主机 IP。车端仓库已交付配置文件 `config/cyclonedds.sidecar.sim.xml`（peer=10.0.0.60）。sidecar ROS2 进程启动前设置：

```bash
export RMW_IMPLEMENTATION=rmw_cyclonedds_cpp
export ROS_DOMAIN_ID=42
export CYCLONEDDS_URI=file:///path/to/cyclonedds.sidecar.sim.xml   # peers 含车端 IP
unset ROS_DISCOVERY_SERVER
unset ROS_LOCALHOST_ONLY
```

验证方法同第 4 节中的 `robot_state` 命令。CycloneDDS 不能与 FastDDS 跨 RMW 互通，车端与 sidecar 必须同时切换。

## 7. 使用实车建图（c30_1）

`slam.sh` 不经过 Discovery Server，车辆端和服务器端通过 DDS 广播直接发现。
前提是两端处于同一网段且 `ROS_DOMAIN_ID` 一致。

### 终端 1：车端启动 SLAM（c30_1）

```bash
./scripts/launch/slam.sh \
  --profile raspberry \
  --namespace c30_1 \
  --no-rviz
```

- `--profile raspberry`：使用树莓派硬件配置（RPLIDAR C1 + STM32 底盘，domain_id=30）
- `--no-rviz`：不在车端启动 RViz，由服务器端远程可视化

确认车端节点已启动：

```bash
ros2 node list | grep c30_1
```

### 终端 2：服务器端启动 RViz

在 Ubuntu 服务器（如 `10.0.0.60`）上执行：

```bash
export ROS_DOMAIN_ID=30
export RMW_IMPLEMENTATION=rmw_cyclonedds_cpp
export CYCLONEDDS_URI=file:///path/to/cyclonedds.xml   # peers 含车端 IP，禁 multicast
unset ROS_LOCALHOST_ONLY
rviz2 -d /home/hello/lidar-slam/config/slam.rviz
```

RViz 将订阅 `/c30_1/map`、`/c30_1/scan`、`/tf` 等 topic，实时显示建图过程。

### 遥控建图

车端可通过手柄遥控行驶：

```bash
./scripts/launch/slam.sh \
  --profile raspberry \
  --namespace c30_1 \
  --joystick \
  --no-rviz
```

或通过服务器端键盘遥控（需保证网络延迟可接受）：

```bash
export ROS_DOMAIN_ID=30
ros2 run teleop_twist_keyboard teleop_twist_keyboard --ros-args -r /cmd_vel:=/c30_1/cmd_vel
```

### 保存地图

建图完成后，在车端执行：

```bash
./scripts/launch/save_map.sh -f maps/c30_1_map
```

如需在服务器端使用该地图，可通过 `scp` 拷贝：

```bash
scp hello@<车端IP>:/home/hello/lidar-slam/maps/c30_1_map.* /home/hello/lidar-slam/maps/
```

---

## 8. 注意事项

1. 所有节点必须在同一个 `ROS_DOMAIN_ID` 下；仿真默认 `42`，实车默认 `30`
2. 确保车辆、仿真机与 sidecar 之间网络可达（CycloneDDS unicast peer 主机互通；不再依赖固定端口 11811）
