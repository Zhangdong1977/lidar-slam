---

## 1. 概述

针对《ROS2 端上下货动作实现方案-2026-05-29》中定义的接口规范，已在仿真环境中完成 Action 接口定义和 GUI 仿真工具开发。

## 5. Action Server 行为说明

### 5.1 Goal 验证

收到 Goal 后校验：

| 校验项 | 失败行为 |
|--------|----------|
| `job_id` 不为空 | REJECT |
| `materials` 不为空 | REJECT |
| `vehicle_name` 与本地匹配 | WARN（不拒绝） |

### 5.2 执行流程

```
Sidecar 发送 Goal
  → Goal 验证（job_id、materials）
  → Feedback: ACCEPTED (0%), CHECKING (10%)
  → GUI 显示物料清单，等待操作员操作
  → 操作员点击按钮
  → Feedback: VERIFYING (90%), COMPLETING (100%)
  → 返回 Result
```

### 5.3 结果判定

仿真 GUI 的操作方式：

| 操作 | 结果 | 说明 |
|------|------|------|
| 全部勾选 + 提交 | `SUCCEEDED` | 所有物料 actual_quantity = quantity |
| 部分勾选 + 提交 | `PARTIAL` | 勾选的物料 SUCCEEDED，未勾选的 FAILED |
| 全部不勾选 + 提交 | `FAILED` | 所有物料 actual_quantity = 0 |
| 点击 [全部失败] | `FAILED` | 忽略勾选状态，error_code = LOAD_FAILED/UNLOAD_FAILED |
| 点击 [取消] | `CANCELLED` | 取消当前操作 |

### 5.4 Cancel 处理

- 收到 Cancel 请求后立即接受
- GUI 显示取消状态
- 返回 `status=CANCELLED`

## 6. Sidecar 对接

Action 名称按 namespace 暴露：

```text
/{namespace}/load_materials
/{namespace}/unload_materials
```

当前仿真配置中 namespace 为空，实际路径为：

```text
/load_materials
/unload_materials
```

若 Sidecar 使用车辆名作为 namespace（如 `ackermann_robot`），需在 launch 参数中设置 `namespace:=ackermann_robot`。

## 9. 实车迁移指南

仿真代码中 Action Server 的架构已预留硬件驱动层接口。实车迁移时需：

1. **替换 `material_action_server.py` 中的 stub 逻辑**：将操作员手动确认替换为硬件驱动调用
2. **实现 `drivers/plc_driver.py`**：对接真实 PLC/机械臂/输送线
3. **添加 Feedback 真实阶段**：根据传感器反馈发布 `MOVING_ACTUATOR`、`PICKING`、`PLACING`、`VERIFYING` 等阶段
4. **实现超时机制**：在 execute callback 中添加硬件操作超时
5. **添加 `/{namespace}/load_state` Topic**：发布车辆载具实时状态

Action 接口定义（Goal/Result/Feedback 字段）**无需修改**，Sidecar 对接代码可直接复用。
