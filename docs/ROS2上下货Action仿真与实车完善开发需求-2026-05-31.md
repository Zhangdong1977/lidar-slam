# ROS2 上下货 Action 仿真与实车完善开发需求

日期：2026-05-31  
面向团队：ROS2 仿真 / 实车控制团队  
参考报告：`docs/JVS-VGA控制台-仿真实现报告-2026-05-30.md`

---

## 1. 背景

ROS2 端报告已完成 `LoadMaterials.action`、`UnloadMaterials.action`、`MaterialSpec.msg`、`MaterialActual.msg`、Action Server、Cancel、Feedback 与 JVS-VGA 控制台仿真工具。当前实现能支撑 Gazebo 仿真环境中由操作员手动确认上下货结果。

本地 `jvs-opentcs` 与 `jvs-opentcs-ros2-sidecar` 已按该接口继续加固：Sidecar 不再在消息包缺失、Action Server 未就绪或下发异常时返回伪 `ACCEPTED`，并已按 `LOAD/UNLOAD` 分别调用 `/load_materials` 与 `/unload_materials`。因此 ROS2 侧后续完善应保持现有 Action 字段兼容，重点补齐实车状态、超时、反馈阶段和硬件驱动替换点。

---

## 2. 接口兼容要求

以下接口字段保持不变，避免 Java / Sidecar / ROS2 三方重复改合同：

```text
jvs_agv_material_msgs/action/LoadMaterials
jvs_agv_material_msgs/action/UnloadMaterials
jvs_agv_material_msgs/msg/MaterialSpec
jvs_agv_material_msgs/msg/MaterialActual
```

Action 名称继续按 namespace 暴露：

```text
/{namespace}/load_materials
/{namespace}/unload_materials
```

若仿真 namespace 为空，则路径为：

```text
/load_materials
/unload_materials
```

Result 状态必须使用既有枚举语义：

```text
SUCCEEDED / PARTIAL / FAILED / CANCELLED / TIMEOUT
```

## 3. ROS2 侧待完善需求

### 3.1 载具物料状态 Topic

新增可订阅 Topic：

```text
/{namespace}/load_state
```

建议消息内容至少包含：

```yaml
vehicle_name: string
active_job_id: string
order_id: string
current_load: MaterialActual[]
required_materials: MaterialSpec[]
unload_materials: MaterialSpec[]
phase: string
progress: float32
updated_at: builtin_interfaces/Time
```

验收点：

- 上下货 Action 进入 `RUNNING` 后，`load_state` 能显示 `active_job_id`。
- Result 终态后，`current_load` 与 Result 中的 `current_load` 一致。
- Cancel / Timeout 后，`active_job_id` 清空或标记为终态。

### 3.2 Action 自动超时

Action Server 必须支持自动超时，不能只依赖 GUI 操作员手动结束。

要求：

- 每个 Goal 启动时记录开始时间和 timeout 配置。
- 超时后返回 `success=false`、`status=TIMEOUT`、`error_code=MATERIAL_ACTION_TIMEOUT`。
- 超时后 GUI 状态进入终态，不允许继续提交成功结果。
- 超时后仍要返回 `current_load`，便于平台侧做库存核对。

建议配置项：

```yaml
material_action:
  default_timeout_ms: 60000
  load_timeout_ms: 60000
  unload_timeout_ms: 60000
```

### 3.3 Cancel 与 Result 语义一致

Cancel 处理必须满足：

- 收到 cancel request 后尽快停止 GUI / 硬件流程。
- 若流程可取消，返回 `status=CANCELLED`。
- 若流程已终态，不能重新覆盖结果。
- Cancel 后不得再发布 `SUCCEEDED` / `PARTIAL` Result。

验收矩阵：

| 场景 | 期望结果 |
|---|---|
| Goal 等待操作员确认时 cancel | Result `CANCELLED` |
| Goal 硬件动作执行中 cancel | 尽力停止硬件，Result `CANCELLED` 或 `FAILED`，错误码说明原因 |
| Goal 已 `SUCCEEDED` 后 cancel | cancel 不覆盖已完成结果 |
| Goal 超时后 cancel | cancel 不覆盖 `TIMEOUT` |

### 3.4 Feedback 真实阶段

当前仿真阶段较固定，需要补充更接近实车的阶段反馈。建议阶段枚举：

```text
ACCEPTED
CHECKING
MOVING_TO_STATION
MOVING_ACTUATOR
PICKING
PLACING
VERIFYING
COMPLETING
```

要求：

- `phase` 必须体现当前真实动作，不只发送固定文本。
- `progress` 必须单调递增，范围 `0.0-1.0`。
- `message` 应包含可排障信息，例如传感器状态、PLC 步骤或 GUI 操作说明。
- Feedback 不应刷屏，阶段变化或进度明显变化时发布即可。

### 3.5 硬件驱动替换点

需要把 GUI 仿真层与真实硬件驱动层解耦。建议定义统一驱动接口：

```python
class MaterialActionDriver:
    def load(self, goal) -> MaterialActionDriverResult:
        ...

    def unload(self, goal) -> MaterialActionDriverResult:
        ...

    def cancel(self, job_id: str) -> bool:
        ...

    def current_load(self, vehicle_name: str) -> list:
        ...
```

实车侧至少预留以下驱动实现：

- `drivers/plc_driver.py`：PLC / IO 点位控制。
- `drivers/robot_arm_driver.py`：机械臂抓取 / 放置。
- `drivers/conveyor_driver.py`：输送线 / 顶升 / 滚筒控制。
- `drivers/sensor_driver.py`：到位、夹紧、货物存在、扫码确认。

仿真 GUI 应作为 `ManualGuiMaterialActionDriver`，不应与 Action Server 主流程强绑定。

### 3.6 GUI 展示要求

JVS-VGA 控制台必须显示以下字段，便于和 openTCS / Sidecar 联调对账：

- `jobId`
- `requestId`
- `orderId` / `orderNo`
- `stepNo`
- `vehicleName`
- `pointId`
- `locationId`
- `operation`
- `expectedMaterials`
- `currentLoad`
- 当前 `phase`
- 当前 `progress`
- `errorCode` / `message`

GUI 提交 Result 时必须保留 `jobId` 和 `operation`，并区分 `actual_loaded` / `actual_unloaded`。

## 4. CLI 验收命令

接口存在性：

```bash

ros2 interface show jvs_agv_material_msgs/action/UnloadMaterials
ros2 interface show jvs_agv_material_msgs/msg/MaterialSpec
ros2 interface show jvs_agv_material_msgs/msg/MaterialActual
```


## 5. 异常验收矩阵

| 场景 | 触发方式 | 期望结果 |
|---|---|---|
| 缺少 `job_id` | CLI 发送空 `job_id` | Goal reject |
| 缺少 `materials` | CLI 发送空数组 | Goal reject |
| 操作员全部失败 | GUI 点击全部失败 | Result `FAILED`，有 `error_code` |
| 操作员部分完成 | GUI 只勾选部分物料 | Result `PARTIAL`，失败物料带 `status=FAILED` |
| 执行中 cancel | `ros2 action cancel` 或 Sidecar cancel | Result `CANCELLED` |
| 超时 | 不操作 GUI 或模拟硬件无响应 | Result `TIMEOUT` |
| 硬件异常 | PLC / 机械臂返回错误 | Result `FAILED`，`message` 包含硬件错误 |
| 状态 Topic | Action 执行期间订阅 `load_state` | `active_job_id`、`phase`、`progress` 持续更新 |

## 6. 交付要求

ROS2 团队完成后需提供：

1. 接口包与 Action 包源码路径。
2. launch 参数说明，尤其是 namespace、timeout、GUI/硬件驱动模式切换。
3. `load_state` Topic 消息定义和示例输出。
4. Cancel、Timeout、FAILED、PARTIAL 四类异常结果截图或日志。
5. 与 Sidecar 联调记录：Action Server ready、Goal accepted、Feedback、Result、Cancel 至少各一条证据。
