## 一、接口兼容性

**无变更。** 以下接口字段和命名保持不变，Sidecar 无需任何改动：

```text
jvs_agv_material_msgs/action/LoadMaterials      — 字段不变
jvs_agv_material_msgs/action/UnloadMaterials     — 字段不变
jvs_agv_material_msgs/msg/MaterialSpec            — 字段不变
jvs_agv_material_msgs/msg/MaterialActual          — 字段不变
```

Action 名称路径：

```text
/{namespace}/load_materials
/{namespace}/unload_materials
```

namespace 为空时仍为 `/load_materials`、`/unload_materials`，与当前 Sidecar 配置一致。

## 二、P0 实现情况

### 2.1 Action Server 可用性

✅ 已验证。`/{namespace}/load_materials` 和 `/{namespace}/unload_materials` Action Server 在节点启动后立即可用，可通过以下命令确认：

```bash
ros2 action list | grep load_materials
ros2 action list | grep unload_materials
```

### 2.2 Result 状态全覆盖

✅ 五种 Result 状态均已实现：

| status | success | error_code | 触发场景 |
|--------|---------|------------|----------|
| `SUCCEEDED` | true | 空 | 所有物料操作成功 |
| `PARTIAL` | true | 空 | 部分物料成功、部分失败 |
| `FAILED` | false | `LOAD_FAILED` 或 `UNLOAD_FAILED` | 全部失败 |
| `CANCELLED` | false | 空 | Sidecar 或操作员发起取消 |
| `TIMEOUT` | false | `MATERIAL_ACTION_TIMEOUT` | 超过超时时间未完成 |

**新增 `TIMEOUT` 状态**：之前版本无超时机制，本次已补齐。超时后 Result 中仍包含 `current_load` 字段，便于平台侧做库存核对。

### 2.3 Cancel 语义一致

✅ Cancel 行为已按验收矩阵实现：

| 场景 | 行为 |
|------|------|
| 等待操作员确认时 cancel | 立即停止，返回 `CANCELLED` |
| 执行中 cancel | 尽力停止，返回 `CANCELLED` |
| 已 `SUCCEEDED` 后 cancel | 不覆盖，原结果保持 |
| 已 `TIMEOUT` 后 cancel | 不覆盖，原结果保持 |

**关键保障**：Cancel 后不会再返回 `SUCCEEDED` / `PARTIAL`。已终态（成功/超时）的目标不会被 cancel 覆盖。

### 2.4 Goal 校验

✅ 保持不变：
- 空 `job_id` → Goal REJECT
- 空 `materials` 数组 → Goal REJECT
- `vehicle_name` 不匹配 → 警告但接受

## 三、P1 实现情况

### 3.1 Action 自动超时

✅ 已实现。每个 Goal 启动时记录时间戳，在配置的超时时间后自动返回 `TIMEOUT`。

**可配置参数**（`material_action.yaml`）：

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `action_timeout_ms` | 300000 (5分钟) | 全局默认超时 |
| `load_timeout_ms` | -1 | 装货专属超时，-1 使用默认值 |
| `unload_timeout_ms` | -1 | 卸货专属超时，-1 使用默认值 |

Sidecar 无需关心超时参数——如果超时，ROS2 侧会主动返回 `TIMEOUT` Result。但 Sidecar 也可自行设置客户端超时作为双重保障。

### 3.2 Feedback 真实阶段

✅ 已实现。Feedback 输出以下阶段（按顺序）：

```text
ACCEPTED        → 目标已接受
CHECKING        → 物料清单检查
MOVING_TO_STATION → 移动至站点
MOVING_ACTUATOR → 执行器定位
PICKING / PLACING → 拾取/放置（等待操作员确认）
VERIFYING       → 结果验证
COMPLETING      → 完成
```

特性：
- `progress` 单调递增，范围 0.0 ~ 1.0
- `message` 包含当前动作的可读描述（如站点名、物料数量）
- 阶段变化时才发布，不刷屏

### 3.3 GUI 联调信息展示

✅ 已增强。JVS-VGA 控制台在 Action 面板中展示以下字段：

| 展示项 | 来源字段 |
|--------|----------|
| Job ID | `job_id` |
| 订单 | `order_no` / `order_id` |
| 点位 | `point_id` |
| 位置 | `location_id` |
| 车辆 | `vehicle_name` |
| 阶段 | Feedback `phase` |
| 进度 | Feedback `progress` |

状态栏实时显示阶段名（中文）和进度条，超时/取消/完成均有明确的日志记录。

## 五、Sidecar 对接影响评估

| 项目 | 影响 |
|------|------|
| Action 字段 | 无变更，无需改动 |
| Action 路径 | 无变更，无需改动 |
| Result 新增 `TIMEOUT` | Sidecar 需确认能处理 `status=TIMEOUT` |
| Result 新增 `CANCELLED` | 之前 cancel 返回方式不同，Sidecar 需确认识别 `status=CANCELLED` |
| Feedback 阶段名新增 | Sidecar 如有阶段展示，可识别新阶段名；纯日志场景无影响 |
| 超时行为 | Sidecar 自身超时可作为双重保障，不会与 ROS2 侧超时冲突 |

**建议 Sidecar 确认**：`status=TIMEOUT` 和 `error_code=MATERIAL_ACTION_TIMEOUT` 的处理逻辑是否已覆盖。
